## 3. Сұрақтарға жауаптар

**1. v1 мен v2 өлшемдерінің айырмашылығы неге осындай? Көпсатылы жинаудың бұл жобадағы басты пайдасы неде?**

v1 образы 84.8MB, v2 образы 83MB, яғни айырма бар болғаны шамамен 1.8MB. Жобада сыртқы кітапхана жоқ, тек Python-ның стандартты модулдері бар, сондықтан салмақтың дерлік бәрін базалық `python:3.12-alpine` образы (83.6MB) құрайды. v2 тек бастапқы код, тест және жинау скрипттерінен босағандықтан ғана аздап жеңіл. Сондықтан көпсатылы жинаудың басты пайдасы орын үнемдеуде емес, тексеруде: тесттен өтпеген дерек финалдық образға жетпейді.

**2. 3-кезеңде қай тест құлады? Неге sayakhat-auto:bad образы пайда болмады?**

Құлаған тест — `test_plate_format`. Ол 37-жолдағы `123ABC01` нөмірін қабылдамады, себебі regex `^[0-9]{3}[A-Z]{3}02$` аймақ коды тек `02` болуын талап етеді, ал онда `01` тұрды. Тест құлаған кезде `RUN python -m unittest discover -s tests -v` қадамы 1 кодымен аяқталды, ал Docker жинауды сол жерде тоқтатты. Финалдық саты орындалмай, образ экспортталмағандықтан, `sayakhat-auto:bad` тізімде пайда болған жоқ.

**3. 4-кезеңде қай қадамдар CACHED болды және неге? records.csv өзгергенде қай қадамдар қайта орындалады?**

4-кезеңде `build` пен `test` сатыларының бәрі `CACHED` болды: `WORKDIR /src`, `COPY tools/`, `COPY data/`, `RUN python tools/build_report.py`, `COPY tests/` және `RUN python -m unittest ...`. Себебі мен тек `app/server.py` файлын өзгерттім, ал басқа файлдарға тиіскен жоқпын, сондықтан тек финалдағы `COPY app/server.py` мен `COPY --from=test` қадамдары қайта орындалды. Егер `records.csv` өзгерсе, `COPY data/` кэші бұзылады. Содан кейін `RUN python tools/build_report.py`, `COPY tests/` және тесттерді жүргізу қайта орындалады, мұны 3-кезеңдегі `3-build-bad.txt` логынан көруге болады.

**4. Финалдық саты report.json-ды test сатысынан емес, build сатысынан алса, не болар еді?**

Егер финалдық сатыда `COPY --from=build /src/out/report.json .` деп жазсақ, финалдық образ `test` сатысына тәуелді болмай қалады. Docker (BuildKit) финалға қажет емес сатыны орындамайды, сондықтан `test` сатысы мүлде іске қосылмайды. Сонда `test_plate_format` сияқты тесттер қате деректі тоқтата алмай, `bad` образы да жасалып кетер еді. Демек, тексеру қақпасы жұмыс істемейді.

**5. web контейнері API контейнерін қалай табады? Неге web контейнерінің ішінде localhost:8080 мекенжайы жұмыс істемейді?**

Екі контейнер де бір `auto-net` желісінде тұр: `auto-api` — 172.21.0.2, `auto-web` — 172.21.0.3. Желінің ішкі DNS қызметі `auto-api` атын сол IP-ге аударады, сондықтан `nginx.conf` ішіндегі `proxy_pass http://auto-api:8080;` жұмыс істейді. Ал web контейнерінің ішіндегі `localhost` Nginx тұрған контейнердің өзі, ал 8080 портын тек API тыңдайды. Сондықтан web ішінен `localhost:8080` арқылы API-ге жету мүмкін емес.

## 4. Қиындықтар

3-кезеңде көпсатылы Dockerfile жинап көргенде образ құрылмай, мынадай қате шықты: `AssertionError: Regex didn't match: '^[0-9]{3}[A-Z]{3}02$' not found in '123ABC01'` және `ERROR: process "/bin/sh -c python -m unittest discover -s tests -v" did not complete successfully: exit code: 1`. Себебі `records.csv` ішіне нөмірі `123ABC01` болатын қате жазба қосқанмын, ал тест аймақ коды `02` болуын талап етеді. Оны шешу үшін 37-жолдағы қате жазбаны жойдым да, жинауды қайта іске қостым. Сонда 35 жазбамен 6 тесттің бәрі өтіп, `sayakhat-auto:v2` образы сәтті құрылды.
